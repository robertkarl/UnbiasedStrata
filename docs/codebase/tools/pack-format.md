# On-disk pack and draft-pack formats

## Purpose

This page describes every file the offline tools write and the engine reads: the trunk's **native pack**,
the **Qwen3.6 draft pack**, the **Flash-Next draft head** runtime directory, and the **canonical Q2_0 pack**
(legacy). The description comes from the writers (`tools/iq_pack.py`, `tools/mtp_qwen36_pack.py`,
`tools/mtp_rt.py`, `tools/make_profile.py`, `tools/strata_tokenizer.py`, `tools/pack_index.py`,
`tools/strata_pack.py`) and was checked against the readers in the engine (`src/core/weights.cpp`,
`src/kernels/cpu/expert_layout.cpp`, `src/core/expert_cache.cpp`, `src/core/mtp.cpp`). Where the two sides
disagree, this page says so. How the engine's expert code uses these files at run time is described in
[Core › Experts › Pack format](../core/experts/pack-format.md).

Files covered here (writers): [`tools/iq_pack.py`](../../../tools/iq_pack.py),
[`tools/mtp_qwen36_pack.py`](../../../tools/mtp_qwen36_pack.py), [`tools/mtp_rt.py`](../../../tools/mtp_rt.py),
[`tools/make_profile.py`](../../../tools/make_profile.py), [`tools/draft_vocab.py`](../../../tools/draft_vocab.py),
[`tools/strata_tokenizer.py`](../../../tools/strata_tokenizer.py), [`tools/pack_index.py`](../../../tools/pack_index.py),
[`tools/strata_pack.py`](../../../tools/strata_pack.py), [`tools/pack_layer.py`](../../../tools/pack_layer.py).

## 1. Trunk native pack (`tools/iq_pack.py`)

Written by `python3 -I tools/iq_pack.py --gguf <shard 1>.gguf --out <dir>`. This is the pack both supported
models use (Flash-Next `pack-iq3-xxs`, Qwen3.6 `qwen36-q4` / `qwen36-iq3`; the commands are in
[UPSTREAM.md](../../../UPSTREAM.md)). Quantized tensors are not copied: the engine serves them from the GGUF
itself (`strata --native <shard1> --pack <dir>`), so the pack holds only the float tensors and the maps.

| File | Always? | Written by | Read by |
| --- | --- | --- | --- |
| `index.txt` | yes | `write_index` (`tools/iq_pack.py:452`) | `WeightTable::load` / `pool_bytes` / `index_code_bits` (`src/core/weights.cpp:89-191`) |
| `dense.bin` | yes (hard-linked from the base pack with `--base`) | `index_standalone` (`tools/iq_pack.py:349`) | `WeightTable::load` |
| `native_experts.txt` | yes; the **completion marker**, written last | `main` (`tools/iq_pack.py:733-736`) | `expert_layout_load` (`src/kernels/cpu/expert_layout.cpp:233`) |
| `conversions.json` | standalone packs | `index_standalone` (`tools/iq_pack.py:423-435`) | nothing in the engine; an audit record |
| `tokenizer/` | when `tokenizer/vocab.json` or `chat_template.jinja` is missing | `strata_tokenizer.py extract` (subprocess, `tools/iq_pack.py:718-720`) | not read by the engine (`src/program/generate.cpp:9` says it has no tokenizer); the C++ front end tokenizes from the GGUF with llama.cpp |
| `expert-profile.bin` | when `--expert-profile` is given, or for `qwen35moe` when `data/qwen36-expert-profile.bin` fits | copied (`tools/iq_pack.py:721-725`) | `read_expert_profile` (`src/core/expert_cache.cpp:23`) via `--expert-profile` |
| `experts.bin` + `experts.bin.src.json` | only with `--experts-bin` | `main` (`tools/iq_pack.py:744-758`) | the expert loader; if present it is read **instead of** the GGUF |
| `compat-bf16.json` | only with `--compat-bf16` | `index_standalone` (`tools/iq_pack.py:443-446`) | audit record |
| `extra.bin` | only with `--base` | `index_from_base` (`tools/iq_pack.py:503-506`) | `WeightTable::load` (file id 3) |

### 1.1 `index.txt`

Text, one header pair then one row per non-expert tensor:

```
# strata pack index v3 -- generated by tools/iq_pack.py (native experts) from <shard1 name>
# align 64 pool <arena bytes> tensors <n>
<name> <file> <kind> <src_off> <src_bytes> <dst_off> <dst_bytes> <ne0> <ne1> <code_bits> <code_bias> <group_elems> <codebook> <has_offset> <codes_bytes> <scales_bytes> <offset_bytes> <scales_fp16> <act_kind>
```

The 19-column layout is the canonical pack's (defined by `tools/pack_index.py`, section 4 below); the engine
parses every row with one `sscanf` and refuses a row that does not yield 19 fields
(`src/core/weights.cpp:164-177`). The `# align ... pool ... tensors ...` line is mandatory: `pool` is the arena
size the engine allocates.

Columns as `iq_pack.py` fills them:

| Column | Meaning in a native pack |
| --- | --- |
| `file` | 0 = `dense.bin`, 3 = `extra.bin` (`--base` only). The engine's `file_name` also knows 1 = `embd.bin`, 2 = `experts.bin` (canonical pack) (`src/core/weights.cpp:64-71`). |
| `kind` | **4** = raw BF16 copied (engine form `Bf16InF32`), **5** = raw F16 copied (engine form `F16InF32`), **2** = F32 copied, **3** = F32 bytes in `dense.bin` that the loader narrows to F16 with round-to-nearest-even (PLE conv, Flash-Next only), **0** = served natively from the GGUF. The loader maps 4 and 5 to kinds 1 and 3 with `raw16 = true` (`src/core/weights.cpp:180-187`). |
| `src_off`, `src_bytes` | offset and length in the file named by `file`; each tensor is padded to 64 bytes. 0 for native rows. |
| `dst_off`, `dst_bytes` | arena placement; `dst_off` is rewritten as the running 64-aligned sum by `write_index` (`tools/iq_pack.py:453-456`). `dst_bytes` differs from `src_bytes` only for kind 3 (half). Native rows carry `dst_bytes = 0`. |
| `ne0`, `ne1` | GGUF shape, `ne0` contiguous; `ne1 = 0` for 1-D tensors. More than 2 dimensions is refused (`tools/iq_pack.py:362-364`). |
| `code_bits code_bias group_elems` | `8 0 32` on native rows (the marker the loader uses: `code_bits != 0 && dst_bytes == 0` means "only in the GGUF form", `src/core/weights.cpp:269-274`), `0 0 1` on pack rows. |
| remaining 7 | always 0 (`codebook has_offset codes_bytes scales_bytes offset_bytes scales_fp16 act_kind`). |

Which tensors go where is decided by the per-architecture `FORM` table (`tools/iq_pack.py:83-110`) and, for
Qwen3.6, the native projection list (`tools/iq_pack.py:116-124`); see [pack-builders.md](pack-builders.md).
Expert tensors (`blk.N.*_exps.weight`) and `per_layer_token_embd.weight` (Flash-Next's PLE table) never appear.
For a `-MTP` file, every `blk.<n_trunk>`+ tensor is left out too.

### 1.2 `dense.bin`

The bytes of every non-native index row, concatenated in index order, each padded to a 64-byte boundary
(`ALIGN = 64`, `tools/iq_pack.py:267`, `:416-421`). Contents are the tensor as stored in the GGUF, or converted to
the engine's form when the `FORM` table demands another (F32 to BF16 by taking the high halves when exact; F16/BF16
to F32 by widening; rounding conversions only with `--compat-bf16`). For both Qwen3.6 files `dense.bin` is
byte-identical (UPSTREAM.md lists the same SHA-256 for `qwen36-q4/dense.bin` and `qwen36-iq3/dense.bin`).

### 1.3 `native_experts.txt`

One line per trunk layer, offsets **absolute in the GGUF shard** that holds each role tensor:

```
# strata native experts v3: layer gu_type d_type offset blob_bytes gate_off up_off down_off [shard] (n_expert <E>, total <bytes>; absolute offsets in <shard1>, or in the named shard beside it)
<layer> <gu_type> <d_type> <offset> <blob_bytes> <gate_off> <up_off> <down_off> [<shard> | <gate_shard>,<up_shard>,<down_shard>]
```

- `gu_type`, `d_type`: ggml type ids of gate/up (must be equal) and down (`tools/iq_pack.py:551-553`).
- `offset`: the layer's start in the **virtual** `experts.bin` (sum of `blob_bytes * n_expert` of earlier layers);
  the engine requires layers to be contiguous in this space (`src/kernels/cpu/expert_layout.cpp:333-341`).
- `blob_bytes`: bytes of one expert's gate + up + down; the engine recomputes it from the types and the model's
  `n_embd x n_ff` and refuses a mismatch (`expert_layout.cpp:290-296`).
- `gate_off up_off down_off`: `data_start + tensor.offset` of each role tensor in its own shard
  (`tools/iq_pack.py:560-561`). Expert `e` of a role starts at `role_off + e * (role bytes / n_expert)`.
- Shard column: absent when all three roles are in the `--gguf` shard; one file name when they share another
  shard; `gate,up,down` (empty field = the `--gguf` shard) when a shard boundary falls inside a layer. The header
  then says `v4`, which only an engine with `kExpertLayoutVersion >= 4` accepts
  (`include/strata/kernels/cpu/expert_layout.hpp:85`, check at `expert_layout.cpp:263-272`).
- `(n_expert E` in the header overrides the engine's compile-time expert count (`expert_layout.cpp:274-279`).
- For a `-MTP` GGUF, the `nextn_predict_layers` last blocks are excluded (`tools/iq_pack.py:532-539`).

Golden copies for real files live in [`tests/data/native_experts/`](../../../tests/data/native_experts/)
(`qwen36-iq3_xxs.txt`, `qwen36-q4_k_xl.txt`, and Flash-Next variants), checked by `tests/core/expert_layout_test.cpp`.

### 1.4 `conversions.json`

```json
{"schema": 1, "tool": "tools/iq_pack.py", "compat_bf16": false,
 "source_shards": [{"name": "...gguf", "size": 123}],
 "tensors": [{"name": "...", "shard": "...", "src_type": "F32", "dst_type": "BF16",
              "method": "f32->bf16: the values are BF16's (low 16 bits zero)", "exact": true,
              "max_abs_err": 0.0, "source_sha256": "..."}]}
```

One record per tensor whose pack form differs from its stored form (`tools/iq_pack.py:410-413`). For Qwen3.6 that
is the 140 F32-to-BF16 records (routers, shared-expert gates, `ssm_alpha`, `ssm_beta`), all exact
([docs/qwen36-port/step4-pack.md](../../qwen36-port/step4-pack.md) section 2).

### 1.5 `experts.bin` and `experts.bin.src.json` (optional)

Only with `--experts-bin`. Per layer, `n_expert` blobs of `[gate rows | up rows | down rows]`, the raw GGUF
slices (`layer_blobs`, `tools/iq_pack.py:683-686`). The sidecar (`experts_source`, `:577-584`) is
`{"schema": 1, "shards": [{name, size}], "native_experts_sha256": ..., "bytes": total}`. An existing
`experts.bin` is reused only when its size, the sidecar, and six sampled blobs (first/last expert of the first,
middle and last layers) match (`:681-700`). An `experts.bin` that belongs to another source is refused unless
`--experts-bin` rewrites it, because the engine would silently prefer it over the GGUF.

### 1.6 `tokenizer/`

Written by `extract` (`tools/strata_tokenizer.py:278`): `vocab.json` (token to id), `merges.txt` (rank order),
`token_type.json`, `tokenizer.json` (`model`, `pre`, `vocab_size`, `n_merges`, `special_ids`,
`add_bos_token: false`, `pre_pattern` = the transcribed `qwen35` regex), and `chat_template.jinja` when the GGUF
has `tokenizer.chat_template`. `iq_pack.py` treats `vocab.json` plus `chat_template.jinja` as "already there".

### 1.7 `expert-profile.bin` (`STRP`)

Little-endian; written by `write_profile` (`tools/make_profile.py:92`) and by the engine's
`--expert-profile-save` (`src/core/expert_cache.cpp:120-140`, same layout):

| Offset | Type | Field |
| --- | --- | --- |
| 0 | `char[4]` | `STRP` |
| 4 | `u32 x 5` | `version` (1), `n_layer`, `n_expert`, `slots`, `n_ranked` |
| 24 | `(u16 layer, u16 expert) x n_ranked` | the ranking, best first |
| after | `i32 x n_layer x n_expert` | slot table: rank of each pair, `-1` if unranked |

The engine refuses a profile whose `n_layer x n_expert` differs from the model's (`expert_cache.cpp:41-49`);
`iq_pack.py` performs the same check before writing anything (`profile_problem`, `tools/iq_pack.py:594-610`).
Shipped: `data/expert-profile.bin` (48 x 512, 24,576 pairs, Flash-Next) and `data/qwen36-expert-profile.bin`
(40 x 256, 10,240 pairs).

### 1.8 Write ordering (crash safety)

`dense.bin`, `index.txt` and `conversions.json` are written to `.tmp` names; `native_experts.txt` is **deleted
first**, then the three are renamed in, then `native_experts.txt` is written to `.tmp` and renamed last
(`tools/iq_pack.py:429-435`, `:730-736`). A pack without `native_experts.txt` is therefore unfinished. The
expert table and the profile are validated before any file changes (`:646-664`).

## 2. Qwen3.6 draft pack (`tools/mtp_qwen36_pack.py`)

Cut from the draft block `blk.<trunk>` of a `-MTP` qwen35moe GGUF (`nextn_predict_layers` must be 1). Passed to the
engine as `--mtp <dir>`; `MtpDrafter::load` selects this format by the trunk's architecture (`src/core/mtp.cpp`).

| File | Contents |
| --- | --- |
| `dense.txt` | one line per dense tensor: `name kind rows cols offset bytes`, name without the `blk.N.` prefix. `kind` = `f32` (the 7 norms), `bf16` (`ffn_gate_inp`, the 1-D `ffn_gate_inp_shexp`), or the stored ggml type in lowercase for the 8 projections (`q8_0` in the shipped file). `rows = ne1`, `cols = ne0`; 1-D tensors are `1 n` (`tools/mtp_qwen36_pack.py:157-195`). |
| `dense.bin` | those tensors' bytes as stored, each at a **256-aligned** offset (`ALIGN = 256`, `:64`). An F32 router whose values are BF16-exact is written as its high halves (`:172-177`). |
| `experts.bin` | `n_expert` blobs `[gate | up | down]` of raw GGUF blocks, in expert-id order (`:202-208`). |
| `native_experts.txt` | the v3 header plus one line `0 <gu_type> <d_type> 0 <blob> 0 <gu_mat> <2*gu_mat>`; here the three role offsets are **inside a blob**, not absolute file offsets (`:209-212`). |
| `mtp.json` | `format` (`strata mtp pack (qwen35moe) v1`), `arch`, `source`, `source_bytes`, `n_embd`, `n_head`, `n_head_kv`, `head_dim`, `n_rot`, `n_expert`, `n_expert_used`, `n_ff`, `n_ff_shexp`, `trunk_layers`, `draft_block`, `experts` {types, blob and matrix bytes}, `dense` {name: type}, `dense_bytes`, `draft_vocab` (`:230-236`). |
| `draft_vocab.bin` | copied from `--draft-vocab` (default `data/draft_vocab.bin` if present); deleted when `none`. |

Engine checks (`MtpDrafter::check_qwen36_pack`, `src/core/mtp.cpp:179-236`): `mtp.json` must contain
`"arch": "qwen35moe"` and its nine geometry integers must equal the trunk's `ModelGeometry`; the 17 required
names must be in `dense.txt` with the right kind (norms `f32` of `n_embd` or `head_dim` elements, routers `bf16`,
projections a type `native_mmvq_supported` accepts) and `eh_proj` must be `n_embd x 2 n_embd`.
`load_qwen36_experts` (`src/core/mtp.cpp:238-277`) requires exactly one layer line, a header `n_expert` equal to the
trunk's, a supported expert type pair, and blob/role offsets equal to `native_expert_layout`. The `mtp.json`
reader is a substring search (`json_int`, `src/core/mtp.cpp:98-107`), so the exact `"key": value` spelling
written by `json.dumps(..., indent=1)` matters.

## 3. Flash-Next draft head runtime (`tools/mtp_rt.py`)

| File | Contents |
| --- | --- |
| `experts.bin` | 512 experts in the canonical Strata blob (1,382,400 B each): gate/up rows interleaved (`2r` = gate row r, `2r+1` = up row r), then down rows; Q2_0 code bytes in one plane, fp16 scales in another (`blob_of`, `tools/mtp_rt.py:48-58`). |
| `dense.bin` | every non-expert tensor, 256-aligned: the ten large projections re-quantized to Q8_0, router and hyper-connection weights BF16, RMSNorm weights F32 **with `+1` added** (Gemma-style) (`:69-103`). |
| `dense.txt` | `name kind rows cols offset bytes`, `kind` in `q8_0 | bf16 | f32`, names with `mtp.` and `layers.0.` stripped. |
| `draft_vocab.bin` | copied in by hand from `data/draft_vocab.bin` (UPSTREAM.md). |

There is no `mtp.json` for Flash-Next; `check_qwen36_pack` is only run for a qwen35moe trunk.

## 4. `draft_vocab.bin`

A raw array of little-endian `int32` token ids (`array("i", ...)`, `tools/draft_vocab.py:316`), no header. The
engine reads it when the draft head binds and computes draft logits only over those rows; a file whose size is not
a positive multiple of 4 is ignored (`src/core/mtp.cpp:575-590`). Shipped: `data/draft_vocab.bin` (106,299 ids)
and `data/draft_vocab_en.bin` (40,525 ids), both for the 248,320-token vocabulary that Flash-Next and Qwen3.6
share.

## 5. Canonical Q2_0 pack (legacy, `strata_pack.py` + `pack_index.py`)

Upstream's first pack form, which bakes in Flash-Next's Q2_0 geometry (blob 1,382,400 B, `pack_layer.py:40-51`).
Neither supported model uses it; it is documented because the engine's index parser and `--base` still refer to it.

- `manifest.json` (`tools/strata_pack.py:214-278`): `format: strata-pack`, `format_version: 1`, `source`
  (shard paths and optional SHA-256), `n_layers`, `align: 64`, `codebooks.IQ4NL`, per-tensor entries (`form` in
  `P16 | P32 | S2 | S4 | S8`, `codes`/`scales`/`offsets` or `values` plane offsets, `scales_fp16`, `file`), the
  `experts` arena description and, if shard 2 exists, `shard2_tensor` (the PLE table left in place).
- `dense.bin`, `embd.bin`: planes per tensor, each 64-aligned.
- `experts.bin` (+ `experts.json` written by `pack_layer.build`, `tools/pack_layer.py:114`): per expert,
  `gate_up codes | down codes | gate_up fp16 scales | down fp16 scales`.
- `index.txt` from `tools/pack_index.py`: the same 19 columns as above, with `kind` 0-3
  (`VERBATIM`, `BF16_IN_F32`, `F32`, `F16_IN_F32`), the S-form fields filled in, and `act_kind` (0 = activations as
  Q8_0, 1 = Q8_K; `VDT` table, `tools/pack_index.py:86-90`). It also writes a third header line naming the columns.

`iq_pack.py --base <canonical pack>` reads that pack's `manifest.json` and `index.txt` and hard-links its
`dense.bin` (`index_from_base`, `tools/iq_pack.py:468-515`).

## Gotchas

- Two alignments: 64 bytes in the trunk pack, 256 bytes in both draft-pack `dense.bin` files.
- `native_experts.txt` role offsets mean absolute shard offsets in a trunk pack but in-blob offsets in a draft pack;
  the header line says which.
- `index.txt` names may not contain spaces (the loader uses `%255s`).
- `tools/pack_index.py` starts with a UTF-8 byte-order mark (visible in `cat -n` output); Python tolerates it.
- `conversions.json`, `compat-bf16.json`, `experts.bin.src.json` and the `tokenizer/` directory are not read by the
  engine binary in this repository; they are audit trails or inputs for other programs.
